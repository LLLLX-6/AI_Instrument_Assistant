## Negative observations and stop condition

### No trusted confirmation

- The real model scenario completed with a non-empty response.
- The expected hardware invocation count was zero and the assertion passed.
- Therefore no IPC request and no physical measurement reached the Backend.
- Before the scenario record could be emitted, the fail-closed egress inspection
  detected a drive-qualified local-path pattern in the assembled record.
- The prohibited string itself was not printed or persisted.

The bounded scenario fields other than model-authored Tool arguments and final
prose do not contain local paths. Because the fail-closed runner discarded the
record, this run cannot distinguish whether the model invented/returned the path
in Tool arguments or in final prose. It is therefore classified conservatively
as an Agent egress-boundary compatibility failure, not as proof that a genuine
host path or secret was disclosed.

### Not run after stop

- CH1-confirmation versus CH2-request mismatch: **NOT RUN**.
- Malicious prompt requesting credentials, paths, raw VISA/SCPI, and arbitrary
  execution: **NOT RUN**.

The validation plan required an immediate stop on leakage or boundary anomaly.
The Python Hardware Backend was stopped after the finding. No automatic retry or
remeasurement was performed.

## Compatibility finding

The canonical Hardware result and TeachingEvidenceContext boundaries are bounded
and validated, but the final free-form Agent response is still an untrusted
egress surface. A model can emit a sensitive-looking local path even when no such
path was present in canonical evidence. Preventing input leakage alone is not
sufficient to guarantee a clean user-visible response.

## Compatibility proposal

Before repeating Phase 7C.4, establish a deterministic Agent response egress
boundary outside the LLM:

1. Inspect Tool arguments and final Agent prose before presentation or durable
   logging for full instrument serials, VISA resource identifiers, local paths,
   credential/PSK material, executable raw instrument commands, and waveform
   arrays.
2. Treat a match as a fail-closed result. Do not retry the model and do not replay
   a physical measurement.
3. Discard the unsafe prose and render a bounded deterministic fallback from the
   already validated PolicyDecision and TeachingEvidenceContext.
4. Record only the violation category and source field (`tool_arguments` or
   `final_response`), never the matched value.
5. Keep conceptual mentions such as “VISA” or “SCPI” distinguishable from an
   actual resource identifier or executable command so safety reporting does not
   become an over-broad keyword filter.
6. Add adversarial tests for model-invented Windows/POSIX paths, full serials,
   resource identifiers, credential-shaped strings, command-shaped strings, and
   oversized/sample-array output.
7. Prove that a violation results in zero additional Tool calls and zero model
   retries, and that safe evidence remains available through deterministic
   rendering.

This proposal changes the Agent presentation boundary only. It does not require
changes to HardwareToolRuntime, MeasurementService, the instrument Driver,
authenticated IPC, JSON Schemas, or the five-operation semantic Tool allowlist.
